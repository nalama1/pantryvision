# Requirements Document

## Introduction

This feature adds an inventory dashboard to PantryVision so users can view products they previously confirmed and saved to DynamoDB. It introduces a new `list-products` Lambda that scans the products table and generates presigned S3 GET URLs for each product image, a new "My Inventory" view in the frontend, and simple top-navigation between the existing Upload flow and the new dashboard. Products expiring within 7 days are visually highlighted so users can act before food goes to waste, directly supporting the product's expiration-alert objective.

## Glossary

- **List_Products_Lambda**: The AWS Lambda function (`list-products`) responsible for retrieving all product records from the Products_Table and generating a Presigned_Image_URL for each one.
- **Products_Table**: The existing Amazon DynamoDB table (`pantryvision-products`) storing product inventory records.
- **Product_Images_Bucket**: The existing private Amazon S3 bucket (`pantryvision-product-images`) storing uploaded product photos.
- **Presigned_Image_URL**: A time-limited, presigned GET URL generated by the List_Products_Lambda that allows the Frontend_App to display an image stored in the Product_Images_Bucket without making the bucket public.
- **Inventory_Dashboard**: The React component that requests the product list from the List_Products_Lambda and renders it as a grid or list of product cards.
- **Frontend_App**: The React single-page application that orchestrates navigation between the Upload flow and the Inventory_Dashboard.
- **Nav_Bar**: The persistent navigation component in the Frontend_App that lets the user switch between the "Upload" view and the "My Inventory" view.
- **Expiring_Soon_Threshold**: A fixed period of 7 days; any Product_Record whose expirationDate falls within this period from the current date is considered "expiring soon."
- **Product_Record**: A DynamoDB item containing: productId, productName, brand, presentation, expirationDate, imageKey, createdAt, quantity, unit.

## Requirements

### Requirement 1: Retrieve All Products with Image URLs

**User Story:** As a household manager, I want to retrieve my full list of saved products with viewable images, so that I can see what I currently have in my inventory.

#### Acceptance Criteria

1. WHEN the Frontend_App sends a GET request to /list-products, THE List_Products_Lambda SHALL retrieve every Product_Record from the Products_Table and return them in an HTTP 200 response as a JSON array.
2. WHEN the List_Products_Lambda retrieves a Product_Record that has a non-empty imageKey, THE List_Products_Lambda SHALL generate a Presigned_Image_URL for that imageKey with an expiration of 300 seconds and include it in the returned item as `imageUrl`.
3. IF a Product_Record has an empty or missing imageKey, THEN THE List_Products_Lambda SHALL return that item with `imageUrl` set to null instead of attempting to generate a Presigned_Image_URL.
4. WHEN the Products_Table contains zero Product_Record items, THE List_Products_Lambda SHALL return an HTTP 200 response with an empty JSON array.
5. IF the Products_Table scan operation fails due to a DynamoDB error, THEN THE List_Products_Lambda SHALL return an HTTP 500 response with error code "INTERNAL_ERROR" and log the error without exposing internal details to the client.
6. WHEN the List_Products_Lambda is invoked via API Gateway, THE List_Products_Lambda SHALL include CORS headers (Access-Control-Allow-Origin: *) in every response.

### Requirement 2: Sort Products by Expiration Date

**User Story:** As a household manager, I want products closest to expiring shown first, so that I can prioritize using or discarding them before they go to waste.

#### Acceptance Criteria

1. WHEN the List_Products_Lambda returns the product list, THE List_Products_Lambda SHALL order items by expirationDate in ascending order, with the soonest expiration date first.
2. WHERE a Product_Record has an empty expirationDate, THE List_Products_Lambda SHALL place that item after all items that have a non-empty expirationDate.

### Requirement 3: Display Inventory Dashboard

**User Story:** As a household manager, I want to see my saved products with their photo and key details, so that I can quickly recognize and review what I have.

#### Acceptance Criteria

1. WHEN the user navigates to the Inventory_Dashboard, THE Inventory_Dashboard SHALL send a GET request to /list-products and render the returned products.
2. WHEN a product item is rendered, THE Inventory_Dashboard SHALL display the product image (using imageUrl), productName, brand, presentation, expirationDate, and quantity with unit.
3. IF a product item has `imageUrl` equal to null, THEN THE Inventory_Dashboard SHALL display a placeholder image in place of the product photo.
4. WHILE the /list-products request is in progress, THE Inventory_Dashboard SHALL display a loading indicator.
5. IF the /list-products request fails, THEN THE Inventory_Dashboard SHALL display an error message and a retry option.
6. WHEN the /list-products response is an empty array, THE Inventory_Dashboard SHALL display an empty-state message indicating no products have been saved yet.

### Requirement 4: Highlight Products Expiring Soon

**User Story:** As a household manager, I want products close to their expiration date to stand out visually, so that I notice them before they are wasted.

#### Acceptance Criteria

1. WHEN a rendered product's expirationDate falls within the Expiring_Soon_Threshold of the current date (inclusive of today, up to and including 7 days from today), THE Inventory_Dashboard SHALL apply a visually distinct highlight style to that product's card.
2. IF a rendered product's expirationDate is earlier than the current date, THEN THE Inventory_Dashboard SHALL apply a visually distinct "expired" style to that product's card, distinguishable from the "expiring soon" style.
3. IF a rendered product's expirationDate is empty, THEN THE Inventory_Dashboard SHALL render that product's card without any expiration-based highlight style.

### Requirement 5: Navigate Between Upload and Inventory Views

**User Story:** As a household manager, I want to switch between adding new products and viewing my saved inventory, so that I can manage my pantry without losing track of either task.

#### Acceptance Criteria

1. THE Frontend_App SHALL display a Nav_Bar with two selectable options: "Upload" and "My Inventory".
2. WHEN the user selects "My Inventory" in the Nav_Bar, THE Frontend_App SHALL display the Inventory_Dashboard and hide the Upload flow.
3. WHEN the user selects "Upload" in the Nav_Bar, THE Frontend_App SHALL display the Upload flow starting from its current state and hide the Inventory_Dashboard.
4. WHEN the Frontend_App loads for the first time, THE Frontend_App SHALL display the Upload flow by default.

### Requirement 6: List Products API Infrastructure

**User Story:** As a developer, I want the list-products Lambda and its API route defined as infrastructure-as-code, so that it can be provisioned consistently with the rest of the system.

#### Acceptance Criteria

1. THE List_Products_Lambda SHALL be defined in a CloudFormation template stored in the /infra directory, following the same structure as the existing Lambda stack templates.
2. THE List_Products_Lambda execution role SHALL have permission to read items (dynamodb:Scan) from the Products_Table only, plus permission to generate presigned URLs (s3:GetObject) on the Product_Images_Bucket only.
3. THE List_Products_Lambda execution role SHALL have the AWSLambdaBasicExecutionRole managed policy for CloudWatch Logs access and no permissions beyond those specified in criteria 2.
4. THE deployed API Gateway resource SHALL expose a GET method on the /list-products resource path that integrates with the List_Products_Lambda using AWS_PROXY integration, and an OPTIONS method returning CORS preflight headers.

## Future Considerations

Pagination is intentionally out of scope for this MVP; /list-products returns the full inventory in a single response. If inventory sizes grow significantly, a future iteration should add limit/next-token based pagination to both the Lambda and the Inventory_Dashboard.
